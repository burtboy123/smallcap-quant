## 4. ⚠️ The ML question — an ambiguity in the record you should know about

The two contemporaneous documents disagree about whether ML was part of the Incumbent's
**selection**:

- `README_2026Q3_parallel.md` describes the Incumbent as *"f≥5 gate, 9-factor composite,
  **ML overlay**, ensemble screens"*.
- `README_2026Q3_gate_driven.md` (same day, the book-lock doc) says the ML overlay is
  *"frozen and explicitly UNPROVEN"*, *"disabled/unproven by construction"*, and that
  *"Any predictive outcome of this forward test must be attributed to the **gate**, not
  the model."*

The code record: **`ML_OVERLAY_ENABLED` did not exist on 2026-06-14** — it was *introduced*
by `832379c` as part of the disable, later that week. Before it existed, `rank_universe()`
would attempt ML scoring unconditionally, and on success it **overwrites `composite_score`
outright** (`factors/composite.py:371-384`) — so ML could have influenced which 13 names
were selected.

**What this does and doesn't mean:**
- Sizing is not a concern — the forward test was **equal-weighted** by design
  (`meta.json`: *"isolates selection, not sizing"*), so any ML effect on Kelly weights was
  neutralized in the measured result.
- Selection cannot be fully ruled out from the record.
- **Per your instruction, ML stays OFF.** The restored book is therefore
  **"Incumbent-minus-ML"** — which is precisely what the gate-driven README says should
  be credited for the win anyway.

I flag this because it means the restored construction is *not guaranteed* to reproduce
the same 13 names, and the Q4 book may differ from the Q3 Incumbent for that reason in
addition to normal data refresh.
